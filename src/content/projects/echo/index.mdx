## The experiment

I wanted to know what a model trained on my own messages would sound like.

It works, which is the funny part and the unsettling part at the same time.

## Preparing the data

A chat export is a long list of messages, each with a sender and a time, but
no idea of where one conversation ends and the next begins. Most of the work
was turning it into something a model could learn from: deciding what counts
as a conversation, who said what, which messages to keep and how to pair a
prompt with a response.

## How I built it

I fine-tuned open-source LLaMA 3 and Gemma 3 models with Unsloth. Its
memory-efficient training let me run the experiments on a single T4, which was
all I had.

I split the application into small services: one for data preparation, one for
training and inference, and a Streamlit front end over both. Everything runs in
Docker on one machine.

<Figure src={architecture} alt="Architecture diagram: a Streamlit frontend, a data preparation service and an Unsloth training backend, all in Docker on one EC2 instance with a Tesla T4." caption="Three Docker containers on one GPU machine." />

## Looking back

Training a model on private conversations made me think harder about whose
data it really is. Half of every chat is someone else's messages.

The data has its own limits too. A chat export reflects who I was speaking to and
what conversations I kept, so the model can only learn from that sample.
