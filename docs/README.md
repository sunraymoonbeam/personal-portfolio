# Documentation

Pick the task first. When a doc and the code disagree, the code and
`src/content.config.ts` win; fix the doc.

| Task | Read |
| --- | --- |
| Run the site | [Repository README](../README.md#run-locally) |
| Add a role, a project or a hobby | [Adding content](authoring.md) |
| Use or add an article component | [MDX components](mdx-components.md) |
| Write or edit any copy | [Writing](writing.md), especially [how he likes an article to read](writing.md#how-he-likes-an-article-to-read) |
| Ask Zack for facts, or find his answers | [Interview notes](interview.md) |
| Check a change before you ship it | [Verification](verification.md) |
| Deploy, redirect, or regenerate the CV preview, cursors or font | [Deployment](deployment.md) |
| Understand why the code is arranged this way | [Astro conventions](astro-conventions.md) |
| Understand the visual rules | [Design](design.md) |
| See what is unfinished | [TODO](../TODO.md) |
| Work as a coding agent | [AGENTS](../AGENTS.md) |

Adding content and Deployment are step-by-step instructions. MDX components
and Verification are reference. Writing, Design and Astro conventions explain
the choices behind the rules.

[`archive/`](archive/) holds past reviews, kept for their history. They are
not current rules: never edit copy from them.
